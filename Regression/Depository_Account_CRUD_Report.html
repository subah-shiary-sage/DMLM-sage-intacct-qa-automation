What this covers

Depository Account create/edit/view/delete tested end-to-end against release www-p303, mirroring the field-by-field and dependent-field approach used for Loan Account. Two full records were created, edited, and one deleted; validation was probed field-by-field on a third blank form to isolate exactly which required fields fail cleanly versus crash. One record remains in the environment as a fixture: Po-0200-Rec––DAC Test Account 001.

Defects 4 found

Ranked most severe first. Screenshots captured live against release www-p303.

DEFECT 1 Saving a blank Create form throws raw Java/JS exceptions instead of field-required messages

Steps to reproduce

  1. Log in, switch to the Lending Management Entity.
  2. Depository Management → Depository account → Create.
  3. Leave every field empty.
  4. Click Save.

Observed

Three raw exception toasts appear instead of "field is required" messages: Cannot invoke "java.lang.Long.longValue()" because the return value of "com.intacct.ds.snl.model.DepositoryAccount.getDepositoryInterestRateKey()" is null, plus two instances of Cannot read properties of undefined (reading 'placeholders'). Isolated by retesting with only Account category filled: the Java NPE is specifically triggered by an empty Interest rate at save time — once Interest rate is populated, every other empty required field (Name, Customer, Vendor, Location) shows its correct friendly message instead. This is the same underlying crash signature documented for Loan Account/Adjustment ("Bug #54 family").

Expected

Saving with Interest rate empty should show "Interest rate is required for depository account." like every other required field — not a raw NullPointerException.

DEFECT 2 Location is silently required but its label carries no red asterisk

Steps to reproduce

  1. Create page → fill every required field except Location.
  2. Click Save.

Observed

Save is blocked with "Location is a required field for depository account." even though the Location label in the Dimensions section shows no red asterisk — every other Dimensions field (Department, Project, Employee, Item, Class, Contract) is genuinely optional and also unmarked, so there is no visual way to tell Location apart before hitting Save. Confirmed on both Create and Edit. Same defect class as Loan Account's undocumented required Location field.

Expected

Location should carry a red asterisk like every other enforced-required field on the form.

DEFECT 3 Account number is marked required (asterisk) but is not actually validated — empty save fails with a generic, unhelpful error

Steps to reproduce

  1. Create page → choose an Account category without a document sequence (e.g. "10––DAC Regression 1 w/o docSeq").
  2. Fill every other required field (Name, Customer, Vendor, Interest rate, Opening date, Location) but leave Account number empty.
  3. Click Save.

Observed

No inline or banner error names Account number. Save fails only with the generic message Could not create the record for entity. Filling in an Account number and retrying succeeds immediately ("Depository account created"), confirming Account number is actually required server-side — the client just never says so.

Expected

Save should show "Account number is a required field for depository account." (or equivalent), matching the clean pattern already used for Name/Customer/Vendor/Location.

DEFECT 4 Three untranslated i18n keys leak to screen readers (accessible-name only, not visible on-screen)

Observed

  • IA.COLLAPSE — aria-label on every section-collapse toggle button (Depository account information / terms / Dimensions / Current account balance), on Create, Edit, and View.
  • IA.MESSAGE_ERROR_LABEL — aria-label on the Create-page save-error alert region; its visible paragraph text is the correct friendly message.
  • IA.TOGGLE_BUTTON_LABEL — aria-label on the List page's List view / Split view toggle button group.

Verified via DOM inspection: in every case the visible text is correct and localized — only the accessible name read aloud by assistive technology is the raw key. Same known-defect signature family as other LME objects, lower severity than a visible leak.

Expected

aria-label values should resolve to translated strings like "Collapse section", "Error", "View toggle" instead of raw i18n keys.

Behavior notes not classified as defects

Customer and Vendor are editable on the Depository Account Edit page

Confirmed via DOM (disabled=false, readOnly=false for both). This differs from Loan Account, where Customer and Vendor lock to read-only immediately on Edit. Live-tested: changing Customer from "1––Power Aerospace Materials" to "2––Logic Solutions" on Edit saved correctly and reflected on View. Documented as a factual difference between the two objects — needs a product-intent call before treating either behavior as the "correct" one.

Account name is not enforced unique

Created a second, distinct record with the exact same name as an existing one ("DAC Test Account 001", same Account category) and it saved without any duplicate/uniqueness error — two records with identical names coexist, distinguished only by their auto-generated Account numbers. Test record deleted afterward to avoid clutter; the fixture original remains.
