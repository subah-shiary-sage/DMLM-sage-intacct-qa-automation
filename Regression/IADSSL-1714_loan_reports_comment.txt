h2. Lending Management — Loan ledger report & Loan roll forward report

Tested on release (www-p303), company SNL_release_monthly, Lending Management Entity, as user Admin. System date at the time of testing was 08/13/2026.

Navigation: *Applications > Lending Management > All > Reports*.

137 checks were run across the two reports: 114 passed, 14 failed and 9 could not be completed. The 14 failures are the 7 defects below (several defects fail more than one check because they affect both reports).

----
h3. Bug #89 [Lending Management > Reports > Loan ledger report / Loan roll forward report]: Choosing the "All Periods" reporting period leaves out the current year's data.

*Steps to reproduce:*
 # Log in and switch to the Lending Management Entity.
 # Go to *Applications > Lending Management > All > Reports > Loan ledger report*.
 # In the *Time period* section, set *Reporting period* to *All Periods*.
 # Leave every other filter at its default and leave *Start date* and *End date* empty.
 # Click *View* and note how many rows are returned and the latest posting date.
 # Click *Customize*, set *Reporting period* back to *Current Month*, and click *View* again.
 # Click *Customize*, clear the *Reporting period*, type *01/01/2015* in *Start date* and *12/31/2026* in *End date*, and click *View*.

*Observed behavior:*
 * "All Periods" returns only 94 rows covering 15 loan accounts, and the latest posting date shown is 04/10/2025. No 2026 activity appears at all.
 * "Current Month" returns 127 rows covering 29 loan accounts, all dated in August 2026.
 * Entering the date range 01/01/2015 to 12/31/2026 by hand returns 218 rows covering 43 loan accounts, dated from 11/01/2017 through 08/13/2026.
 * So "All Periods" is leaving out 124 rows and 28 loan accounts that the report itself will happily show when the same span is typed in as a date range. The accounts returned by "All Periods" and the accounts returned by "Current Month" do not overlap at all.
 * The same thing happens on the Loan roll forward report: the ending balance under "All Periods" is 71,708.24, against 1,001,243,977.44 for the current month.

*Expected behavior:*
 * "All Periods" should include every period, so it should return at least as much as any other reporting period choice, including the current year's transactions.

h3. Bug #90 [Lending Management > Reports > Loan ledger report / Loan roll forward report]: The "As of date" field makes no difference to the report.

*Steps to reproduce:*
 # Log in and switch to the Lending Management Entity.
 # Go to *Applications > Lending Management > All > Reports > Loan ledger report*.
 # In the *Time period* section, set *Reporting period* to *Current Month* and leave *Start date* and *End date* empty.
 # Type *08/03/2026* in the *As of date* field.
 # Click *View* and note the number of rows and the latest posting date.
 # Repeat the same run twice more, first with *As of date* set to *08/13/2026*, then with *As of date* left empty.

*Observed behavior:*
 * All three runs return exactly the same thing: 127 rows across 29 loan accounts, with posting dates running from 08/01/2026 to 08/13/2026.
 * With the date set to 08/03/2026 the report still includes transactions posted on 08/04, 08/05, 08/06 and 08/13. Nothing is excluded.
 * The field accepts the date and keeps it on screen, so there is no clue to the user that it is being ignored.
 * The Loan roll forward report behaves the same way — the totals are identical whatever is entered here.

*Expected behavior:*
 * Setting an "As of date" should leave out transactions posted after that date and show balances as they stood on that date.

*Screenshot:*
!bug90-as-of-date-ignored.png!

h3. Bug #91 [Lending Management > Reports > Loan ledger report / Loan roll forward report]: Filling in only one end of a From/To filter does not filter the report at all.

*Steps to reproduce:*
 # Log in and switch to the Lending Management Entity.
 # Go to *Applications > Lending Management > All > Reports > Loan ledger report*.
 # Set *Reporting period* to *Current Month*.
 # In the *Filters* section, type *LA-COMBO-01* in *From loan account* and leave *To loan account* empty.
 # Click *View* and note which loan accounts are listed.
 # Click *Customize*, clear *From loan account*, type *LA-COMBO-06* in *To loan account*, and click *View*.
 # Click *Customize*, type *2* in *From customer*, leave *To customer* empty, and click *View*.

*Observed behavior:*
 * With only *From loan account* filled in, the report returns all 127 rows and all 29 loan accounts. Accounts that come before LA-COMBO-01 in the sort order, such as CMRRGL#0100#doc and INV0009, are still listed.
 * With only *To loan account* filled in, the report again returns all 127 rows and 29 accounts.
 * With only *From customer* filled in, the report again returns all 127 rows, including the other customer's loans.
 * Filling in both ends does work correctly — LA-COMBO-01 to LA-COMBO-06 returns 18 rows across 4 accounts, and customer 2 to customer 2 returns 13 rows across 2 accounts.
 * Because the report still runs and returns data, the user can easily believe they are looking at a filtered report when they are not.
 * The same behaviour occurs on the Loan roll forward report.

*Expected behavior:*
 * Filling in only *From* should return that value and everything after it; filling in only *To* should return everything up to that value. If a single-sided range is not supported, the report should tell the user that both ends are required rather than silently returning everything.

*Screenshot:*
!bug91-one-sided-range-not-filtered.png!

h3. Bug #92 [Lending Management > Reports > Loan roll forward report]: Fee amounts are missing from the beginning and ending balances, so the report does not add up.

*Steps to reproduce:*
 # Log in and switch to the Lending Management Entity.
 # Go to *Applications > Lending Management > All > Reports > Loan roll forward report*.
 # Set *Reporting period* to *Current Month* and *Report type* to *Summary*.
 # Click *View*.
 # For each row, add the *Beginning balance* to every movement column across the row and compare the result with the *Ending balance*.
 # Click *Customize*, set *Report type* to *Detail*, click *View*, and repeat the same check on each loan row.

*Observed behavior:*
 * On the summary, no row adds up. Power Aerospace Materials is short by 60.00, Logic Solutions by 10.00 and the grand total by 70.00.
 * In each case the shortfall is exactly the amount shown in the *Fee: Adjustments* column, so that column is displayed on the report but is not being counted towards the ending balance.
 * On the detail report the same check across all 46 loan rows fails on exactly 2 rows — Sal#0100#inv (short by 60.00) and Sal#0113#inv (short by 10.00). These are the only two loans that have a fee adjustment; the other 44 rows add up correctly.
 * Interest adjustments are counted correctly (Logic Solutions' 30.09 is included), so the problem is specific to fees.
 * Fee balances are left out as well. For loan Sal#0108#inv the roll forward shows a beginning balance of 2,255.81, which is the principal of 2,055.00 plus interest of 200.81 from the Loan ledger report, with the 154.00 fee balance left out. The ending balance of 200.81 leaves it out too.

*Expected behavior:*
 * The ending balance should equal the beginning balance plus every movement column shown on the report, including fee adjustments, and the beginning and ending balances should include fee amounts. As it stands the columns do not foot to the ending balance, so the report cannot be used to reconcile.

h3. Bug #95 [Lending Management > Reports > Loan roll forward report]: On the summary, the customer rows and the total row use different number formatting.

*Steps to reproduce:*
 # Log in and switch to the Lending Management Entity.
 # Go to *Applications > Lending Management > All > Reports > Loan roll forward report*.
 # Set *Reporting period* to *Current Month* and *Report type* to *Summary*.
 # Click *View*.
 # Compare how the numbers are written on the customer rows against the *Grand total* row.

*Observed behavior:*
 * The customer rows show unformatted numbers such as {{-5,500}}, {{0}}, {{622.5}} and {{60}}.
 * The grand total row on the same report shows {{(7,555.00)}}, {{0.00}}, {{627.50}} and {{70.00}} — two decimal places, with negatives in brackets.
 * So decimal places and the way negatives are written both change from row to row within one report.
 * The detail version of the report formats its rows correctly, so this affects the summary rows only.

*Expected behavior:*
 * All rows on the report should use the same number formatting — two decimal places and one consistent style for negative amounts.
