Bug #25 — Loan account category > Edit

FIXED
Original issue

The Edit page heading exposed the raw internal object path: Edit loan-management/loan-category: <ID>--<Name>.

Expected

A friendly heading such as "Edit loan account category: <Name>", with no internal object path.

Retest steps
  1. Open a Loan account category detail page (e.g. "Test2") and click Edit.
  2. Read the page heading (H1).

The heading now reads "Edit loan account category: 1160" — the internal path loan-management/loan-category is gone.

Note: Minor: the heading shows the record ID (1160) rather than the name; the core object-path leak is resolved.

Bug #26 — Loan account category > Create / Edit

FIXED
Original issue

Field validation errors leaked the internal object name, e.g. "A value is required for the field name of object loan-management/loan-category", and length errors exposed the same path.

Expected

User-friendly messages that name the field, not the internal object — e.g. "Name is required.", "Name cannot exceed 200 characters.", "Description cannot exceed 500 characters."

Retest steps
  1. On the Edit form, set Name to whitespace only and Save.
  2. On the Create form, set Name to 201 characters and Description to 501 characters and Save.
Result

All messages are now clean and user-facing with no object-name leak: "Name is required.", "Name cannot exceed 200 characters.", "Description cannot exceed 500 characters." Verified on both the Create and Edit forms.

Note: Representative create + edit cases were exercised; the fix is systemic (same validation strings on both forms).

Bug #28 — Loan account category > Create

FIXED
Original issue

Creating a category with a duplicate name returned the unfriendly banner "[object Object]" (HTTP 500), with no indication the problem was a duplicate name.

Expected

A clear message such as "A loan account category with this name already exists. Please use a unique name."

Retest steps
  1. On the Create form, enter a Name that already exists (e.g. "Test2") and Save.
  2. Read the error banner.
Result

The error now reads "Another Loan account categories with name Test2 already exists. Use a unique value instead." — the "[object Object]" banner is gone and the duplicate is clearly identified.

Note: Known minor issue: the entity label appears in plural ("Loan account categories") — a Content-Ops label item the dev flagged separately as IADSSL-1531, not a regression of this fix.
