Detailed results

Bug #29 — Loan fee type > Create / Edit / View

FIXED
Original issue

The first mandatory field was mislabelled "Loan type" (with a red asterisk) although it is the fee type's Name.

Expected

Label the field "Name".

Result

The first field is now labelled "Name" on the Create form (and Edit); no "Loan type" label appears.

Bug #30 — Loan fee type > Create / Edit (validation)

FIXED
Original issue

Validation errors leaked internal identifiers, e.g. GL account blank -> "The field feeGLAccountKey cannot be empty ... of the loan-management/loan-fee-type"; whitespace Name -> "... name of object loan-management/loan-fee-type".

Expected

Friendly messages naming the on-screen field, with no internal field names or object paths.

Result

The object-path/internal-name leaks are gone: GL account blank now shows "Fee GL account key: Field is required." (no "loan-management/loan-fee-type", no "feeGLAccountKey"), and the whitespace-name case no longer throws the raw object-path error.

Note: Minor residual: the GL-account message reads "Fee GL account key" (the field key) rather than the on-screen label "GL account".

Bug #31 — Loan fee type > Edit

FIXED
Original issue

The Edit heading exposed the internal path: "Edit loan-management/loan-fee-type: --".

Expected

"Edit loan fee type: ".

Result

The heading now reads "Edit loan fee type: 44" - the "loan-management/loan-fee-type" path no longer leaks.

Note: Minor: shows the record ID (44) rather than the name (same family as Bug #25/#31).

Bug #42 — Loan fee type > View / Edit

FIXED
Original issue

The primary name field was labelled "Loan type" on the View and Edit pages.

Expected

Label it "Name" (consistent with the list column).

Result

The name field on the Edit page is now labelled "Name"; no "Loan type" label remains.

Bug #32 — Loan fee type > Delete (in use)

NOT VERIFIED Not verified
Original issue

Deleting a fee type that is in use by a loan type failed with a raw internal exception: "Cannot invoke 'String.equalsIgnoreCase(String)' because 'entityDef.table' is null" (HTTP 500).

Expected

A friendly message such as "This loan fee type cannot be deleted because it is used by one or more loan types."

Result

Could not verify. Reproducing the fix needs a fee type that is actually in use by a loan type; the attempt to attach a fee type to a loan type (adding a Fee row in Payment priority order and saving) failed with an HTTP 400 in this sandbox, so the in-use delete path could not be reached. Testing a delete on a not-in-use fee type would be destructive and would not exercise this fix.

Note: The developer listed #32 as ready for testing; it simply could not be re-exercised in this session.
