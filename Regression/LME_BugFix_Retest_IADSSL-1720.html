Detailed results

Bug #33 — Loan type > Create

FIXED
Original issue

Adding a Payment-priority row of Type = "Fee" without a Fee type failed with a raw internal error: loan-management/loan-type has a id 27 with invalid values. Consult the online manual... (leaks the internal object name and id).

Expected

A clear message such as "Fee type is required for a Fee line."

Retest steps
  1. Open Loan type > Create and fill all mandatory fields with valid values.
  2. In Payment priority order, add a row, set Type = Fee, and leave Fee type empty.
  3. Click Save.
Result

The error now reads "Fee type is required for a fee line." — no raw object name / id, no "consult the online manual".

Note: All related messages on this save are now user-facing (e.g. "Presentment method is required.", "Payment priority order should contain both principal and interest item…").

Bug #39 — Loan type > List

FIXED
Original issue

The list showed two adjacent columns both labelled "Loan type" — the record name and the Revolving/Non-revolving classification.

Expected

The classification column should have a distinct header such as "Type".

Retest steps
  1. Open Lending Management > Loan type (the Loan types list).
  2. Read the column headers.
Result

The columns are now "Loan type" (name) and "Type" (Revolving / Non-revolving) — distinct headers.

Bug #45 — Loan type > Create

FIXED
Original issue

Leaving "Order Entry transaction definition" blank returned a raw error exposing an internal field name and a regex: The value for the order-entry-txn-definition.key field does not match pattern /^(-?\d+)$/.

Expected

A friendly required-field message, e.g. "Order Entry transaction definition: Field is required."

Retest steps
  1. Open Loan type > Create.
  2. Leave "Order Entry transaction definition" (and the item fields) blank and Save.
Result

The message is now "Order Entry transaction definition: Field is required." — no internal field name, no regex.

Note: Confirmed in the create-form validation summary alongside the other required fields.

Bug #46 — Loan type > Edit

FIXED
Original issue

On the Edit page, "Interest type" was editable and still mandatory but had NO red asterisk (all other mandatory editable fields kept theirs).

Expected

"Interest type" should carry the red asterisk on Edit like the other mandatory fields.

Retest steps
  1. Open any loan type in Edit.
  2. Check the "Interest type" field label for the red asterisk.
Result

"Interest type" now shows its red asterisk (*) on the Edit page, consistent with the other mandatory fields.

Note: Out-of-scope observation: the Edit page heading still leaks the internal path "Edit loan-management/loan-type: <ID>--<Name>" (same family as the Loan Category #25 heading issue) — not part of this ticket.

Bug #47 — Loan type > Create
