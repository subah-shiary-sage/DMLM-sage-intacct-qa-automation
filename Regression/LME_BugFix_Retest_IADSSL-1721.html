Evidence

Bug #13 Fixed

Create - missing Interest rate returned a raw Java exception (NullPointerException) + JS error toasts.

Saving the Create loan form empty now returns clean field-level messages, including “Interest rate is required for loan account.” No HTTP 500, no raw LoanInterestRate.getKey() exception, no “placeholders” JS toasts.

Bug #14 Fixed

Create - whitespace / empty Account number & Account name leaked internal object & field identifiers.

Empty / whitespace Account number and Account name now produce friendly messages with no internal identifiers. The old A value is required for the field id of object loan-management/loan-account / …field name of object… leaks are gone.

Bug #15 Fixed

Create - “Create amortization schedule” revealed required fields whose messages leaked internal JSON paths.

Ticking “Create amortization schedule” reveals Term in months * and First payment date *, both marked required with a red asterisk. Saving no longer leaks /termInMonths or /firstPaymentDate JSON paths.

Bug #19 Fixed

Create - Account name over 200 chars showed the raw i18n key IA.NAME_SHOULD_NOT_EXCEED_200_CHARACTERS.

A 201-character name now shows the readable message “Name should not exceed 200 characters”. The raw resource key is gone.

Bug #20 Fixed

Create - negative Amount leaked the internal path /originationAmount.

A negative Amount now shows “Amount cannot be negative.” with no /originationAmount path leak.

Bug #24 Fixed

Create/Edit - changing the loan type kind left an invalid interest rate, and saving showed a raw error.

Reproduced by selecting loan type 737 (revolving) + rate 326, then switching the loan type to 743 (non-revolving) - the stale rate is left in place. Saving now shows the clean business message “The selected interest rate is not valid for this loan type.” No raw exception or object-path leak.

Bug #50 Fixed

View page - Account category was plain text, not underlined/drillable like Customer & Vendor.

On the Loan View page, Account category now renders as an underlined drillable link (“36--36 up”), styled identically to the Customer and Vendor links.

Bug #21 Not reproducible here (dev-confirmed fixed)

Create - a duplicate Account number returned the raw error “Could not create the record for entity”.

Could not force a duplicate in this sandbox: the only available loan account category (“36--36 up”) auto-generates the account number. A manual value is rejected with the friendly message “Invalid depository account number. This will be set automatically based on the next available sequence.” - so unique numbers are guaranteed and a duplicate cannot be entered through the UI. No raw error leaked. Marked as dev-confirmed fixed.
