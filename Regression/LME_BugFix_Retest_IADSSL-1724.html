Evidence

Bug #1 Fixed

Create - an interest rate of 0 was accepted despite the rule.

Saving a schedule row with rate 0 is now rejected with “Interest rate cannot be zero or negative.” - consistent with the negative-rate rule.

Bug #2 Fixed

Create - the rate field only accepted 2 decimals, not 4.

A 4-decimal rate 5.1234 now saves successfully (“Loan interest rate created”). The backend pattern is now \d{1,4}.

Bug #3 Partially fixed

Create - empty rate returned a raw Java exception (BigDecimal NPE) + JS errors.

The crash is gone - an empty rate no longer throws the raw BigDecimal.doubleValue() NullPointerException / HTTP 500, and the JS “placeholders” toasts are gone (it is now a 400 validation error). However, the replacement message is not the expected “Interest rate is required.” - it still leaks /loanInterestRateEntries/rate and an unresolved ${ENTITY_NAME} template (see Bug #6).

Bug #4 Fixed

Create - a duplicate name showed “[object Object]”.

Saving a second rate with an existing name now shows “A loan interest rate with this name already exists.” (banner + inline). The “[object Object]” text is gone.

Bug #6 Not fixed

Create - validation messages leak regex, JSON paths and internal object names.

Validation messages still leak internal details. A non-numeric rate (“abc”) shows the JSON path /loanInterestRateEntries/rate, the raw regex ^(-?\d+)?(\.\d{1,4})?$, and an unresolved ${ENTITY_NAME} template. Same class of leak appears on the empty-rate and >200-char cases.

Bug #7 Fixed

Create - “Save and new” did not clear the schedule grid.

After “Save and new”, the new blank form opens with an empty schedule grid (“No data to display.”) and a blank Name - the previous row no longer carries over.

Bug #8 Fixed

Create - Notes accepted more than 1000 characters.

A Notes value over 1000 characters is now rejected with “Notes should not exceed 1000 characters.”

Bug #9 Not fixed

Edit - editing an existing schedule row is silently discarded.

Changing an existing row’s rate from 5.1234 to 7.00 and saving reports “Loan interest rate saved”, but the reopened record still shows 5.1234 - the change was silently discarded, exactly as originally reported.

Bug #10 Fixed

Edit - the Edit page title showed the raw internal object name.

The Edit title now reads “Edit loan interest rate: 48--LIR Retest 1724 zero”. The internal loan-management/loan-interest-rate object name is gone.

Bug #63 Fixed

Create - closed-period message leaked the “Snl” prefix and used “SI”.

A start date in a closed period now shows “The schedule start date cannot fall in a period that is closed in Sage Intacct. Choose a start date in an open period.” - no “Snl” prefix and “Sage Intacct” is spelled out.
