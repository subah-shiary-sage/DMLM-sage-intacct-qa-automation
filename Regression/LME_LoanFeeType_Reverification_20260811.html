Headline finding – five “Passed” rows did not hold

Five rows carried a Passed status that came from the 2026-08-06 IADSSL-1719 retest. That retest ran on the www-p308 developer sandbox (/users/ummefaria.tamanna/projects.ia-app, company tahmid_api6) — not on release. Bugs #29, #30 and #31 are genuinely fixed in that dev build, but the fix has not reached release www-p303, where all three still reproduce today. The release checklist had been marked green off a sandbox result.

They are set back to Failed below. This is a bookkeeping correction, not a new regression — no bug needs re-filing, but the fixes should not be treated as shipped.

New defects found (not previously reported)

Both sit on the lister’s bulk (multi-select) delete path, which the checklist did not cover. Added as SL 49 and SL 50. Not yet filed to IADSSL-1714 — the JIRA token was not available in this session.

  • Blank bulk-delete confirmation modal. Selecting rows in the Loan fee types lister and clicking the toolbar Delete opens a confirmation dialog with no title, no message and no list of what will be deleted — only Delete and Cancel. The user confirms a permanent deletion blind. The single-record modal on the detail page is correct by contrast. Reproduced with 1 and with 4 records, stable after a 2s wait. bug89-feetype-bulk-delete-empty-modal.png
  • Bulk-delete toast names the wrong object. After deleting loan fee types the success message reads “Loan types deleted” instead of “Loan fee types deleted”. bug90-feetype-bulk-delete-wrong-toast-loan-types.png

Known defects re-confirmed on release

  • Bug #87 – on Create and Edit. An over-length Name is rejected, but the message leaks the object path and adds a spurious “not in the required format” line. Verified on create (253 chars) and by renaming an existing record on the edit page (249 chars) — identical message. Neither input carries a maxlength, so the user types well past 200 before being told.
  • Bug #88 – on Create and Edit. Duplicate fee type names still save with no uniqueness check. On create, two rows named “QA FeeType Reverify 001” coexisted; on edit, a record renamed to the existing “Loan Fee Type 01” saved cleanly and the lister then showed two rows with that name.
  • Bug #32 – deleting a fee type that is in use is correctly blocked, but surfaces a raw Java error (entityDef.table is null, HTTP 500). Verified end to end this run, which the 2026-08-06 attempt could not do. Editing while in use works, and the record survives the failed delete.
  • Bug #43 / IAUI-616 – untranslated resource keys still leak as aria-labels: IA.MESSAGE_ERROR_LABEL, IA.COLLAPSE, IA.TOGGLE_BUTTON_LABEL, and the lister column header BULK_SELECTED. Note the error key is reused for success toasts, so a successful save is announced to screen readers as an error.
  • View heading still shows the internal record ID (“Loan fee type: 30”) rather than the name.

Coverage strengthened this run

  • SL 24 previously recorded only the primary Save as verified. All three variants were exercised this time: Save, Save and new, and Save and close (lister count 28→29).
  • SL 35 / 39 were previously inferred from the create-page Save. A real edit was performed: Name, Item, Status and Description all changed on one record and all four persisted.
  • SL 48 in-use delete was reached for the first time on release.
  • SL 12 and SL 22 (max-length and duplicate-name) had only ever been exercised on the Create page, though both objectives cover Edit too. Both were re-run against the edit form this time; both fail there as well.

Checked and dismissed

On the edit page at a 1280px viewport, Save and Cancel collapse into the 3-dot overflow menu. This is responsive behaviour, not a defect — at 1745px both render as primary buttons. It is aggravated by the long raw-object-path heading (Bug #31), which consumes header width. No bug filed.

The single-record delete on the detail page redirects to the lister so quickly that the confirmation toast could not be captured. Removal and redirect were both observed; the toast itself is recorded as unconfirmed rather than claimed.
