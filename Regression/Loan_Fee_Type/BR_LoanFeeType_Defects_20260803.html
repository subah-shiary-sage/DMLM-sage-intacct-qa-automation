Defects

Bug #34 [Create / Edit / View]: The Name field is mislabelled "Loan type".

Observed behavior:

The first (mandatory) field on the Create, Edit and View pages is labelled "Loan type" with a red asterisk, but it is actually the fee type's Name: the list column header is "Name", the validation message calls it "Name" ("Name: Field is required."), and the internal field is "name". A loan fee type is not associated with a loan type, so the label is misleading.

Expected behavior:

Label the field "Name" (consistent with the list column and the validation messages).

Attachment:

The mandatory "Loan type *" field actually holds the fee type name ("QA Fee Type Test 001").

Bug #35 [Create / Edit - validation]: Validation messages leak internal field names and object paths.

Observed behavior:

Required-field errors expose raw internal identifiers instead of friendly text:
• GL account left blank → "The field feeGLAccountKey cannot be empty. Fill in the feeGLAccountKey of the loan-management/loan-fee-type."
• Whitespace-only Name (create and edit) → "A value is required for the field name of object loan-management/loan-fee-type."
(By contrast, an empty Name gives a friendly "Name: Field is required.", so the behaviour is inconsistent.)

Expected behavior:

User-friendly messages that name the on-screen field - e.g. "GL account is required." and "Name is required." - with no internal field names or object paths.

Attachment:

GL account blank error leaks the internal field name "feeGLAccountKey" and object path.

Bug #36 [View]: The view page heading shows the internal record ID instead of the fee type name.

Observed behavior:

The detail page heading reads "Loan fee type: 24" (the internal record ID) even though the record name is "QA Fee Type Test 001". The name only appears lower in the body.

Expected behavior:

The detail heading should read "Loan fee type: <Name>", e.g. "Loan fee type: QA Fee Type Test 001".

Attachment:

Detail heading "Loan fee type: 24" uses the internal ID, not the name.

Bug #37 [Edit]: The edit page heading exposes the raw internal object path.

Observed behavior:

The edit page heading reads "Edit loan-management/loan-fee-type: 24--QA Fee Type Test 001", exposing the internal object path "loan-management/loan-fee-type" and the record ID.

Expected behavior:

The edit heading should read "Edit loan fee type: <Name>", e.g. "Edit loan fee type: QA Fee Type Test 001".

Attachment:

Edit heading exposes the internal object path and record ID.

Bug #38 [UI labels / accessibility]: Untranslated resource keys are used as accessibility labels.

Observed behavior:

Several controls carry raw untranslated resource keys as their aria-labels: the error banner "IA.MESSAGE_ERROR_LABEL", the section collapse button "IA.COLLAPSE", and the list view toggle "IA.TOGGLE_BUTTON_LABEL". Screen-reader users hear the raw keys. (Same class of issue as in the Loan Account / Loan Category / Loan Type modules.)

Expected behavior:

These aria-labels should resolve to their translated strings (e.g. "Error", "Collapse section", "Toggle view").

Attachment:

The red error banner's accessibility label is the raw key "IA.MESSAGE_ERROR_LABEL".

What works well

  • Delete flow is correct. Delete opens a proper "Delete loan fee type" modal with a readable message ("The following loan fee type will be permanently deleted: <name>"); Cancel closes it without deleting, and confirming shows a "Loan fee type deleted" toast, redirects to the list and removes the record.
  • 3-dot menu is complete. The view-page 3-dot menu contains BOTH "View audit trail" and "Object definition" (unlike the Loan Account / Loan Category modules, where "Object definition" is missing).
  • A valid create works and persists, an empty Name gives a friendly "Name: Field is required." message, and the GL account / Item dropdowns populate correctly.
