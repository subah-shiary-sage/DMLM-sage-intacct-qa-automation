Bug #1 [Create]: An interest rate of 0 is accepted even though the application states the rate cannot be zero.

Steps to reproduce:

  1. Log in to Sage Intacct at release.intacct.com.
  2. Switch to the Lending Management Entity using the entity selector.
  3. Navigate to Lending Management and open the Loan interest rates list.
  4. Create a new loan interest rate, enter a name, and set the Type to Revolving.
  5. Add a schedule row with a start date of 07/01/2026 and an interest rate of 0.
  6. Click Save.

Observed behavior:

The record is saved successfully with an Active status and an interest rate of 0.00. This is inconsistent with the application’s own rule, because a negative interest rate is correctly rejected with the message "Interest rate cannot be zero or negative."

Expected behavior:

An interest rate of 0 should be rejected with the same message that is shown for negative values, "Interest rate cannot be zero or negative."

Bug #2 [Create]: The interest rate field does not accept four decimal places and only allows values with up to two decimals.

Steps to reproduce:

  1. Log in to Sage Intacct at release.intacct.com.
  2. Switch to the Lending Management Entity using the entity selector.
  3. Navigate to Lending Management and open the Loan interest rates list.
  4. Create a new loan interest rate and add a schedule row with a start date of 08/01/2026 and an interest rate of 5.1234.
  5. Click Save.

Observed behavior:

The value is rejected because the field only accepts one or two decimal places (the backend enforces the pattern ^(-?\d+)?(\.\d{1,2})?$). Both 5.1234 and 5.12345 fail to save, while 5.12 saves successfully.

Expected behavior:

The interest rate field should accept values with up to four decimal places.

Bug #5 [Create]: The toolbar "Add row" button inserts each new schedule row at the top of the grid, which causes a false date-order validation error.

Steps to reproduce:

  1. Log in to Sage Intacct at release.intacct.com.
  2. Switch to the Lending Management Entity using the entity selector.
  3. Navigate to Lending Management and open the Loan interest rates list.
  4. Create a new loan interest rate and set the Type to Revolving.
  5. Click the toolbar "Add row" button and enter a start date of 01/01/2025 with an interest rate of 3.00.
  6. Click the toolbar "Add row" button again and notice that the new row is inserted above the existing row instead of below it.
  7. In the new top row, enter a later start date of 02/01/2025 with an interest rate of 4.00.
  8. Click Save.

Observed behavior:

The save fails with the message "New Start Date cannot be prior or equal to previous Start Date", even though 02/01/2025 is later than 01/01/2025. This happens because the toolbar "Add row" button always inserts the new row at the top of the grid, while the grid requires the start dates to be in ascending order. Using the row-level "+" button, which appends the row at the bottom, with the same dates saves without any error.

Expected behavior:

The toolbar "Add row" button should append new rows at the bottom of the grid, in the same way as the row-level "+" button, and the date-order validation should be based on the actual start dates rather than on the position of the row in the grid.

Attachment:

LIR-CREATE-addrow-top-order-error.png

Bug #11 [Edit]: Editing an existing schedule row’s start date or interest rate is silently discarded when the record is saved.

Steps to reproduce:

  1. Log in to Sage Intacct at release.intacct.com.
  2. Switch to the Lending Management Entity using the entity selector.
  3. Navigate to Lending Management and open the Loan interest rates list.
  4. Open a Revolving loan interest rate that has a multi-row schedule (for example 01/01/2025 = 3.00 and 02/01/2025 = 4.00) and click Edit.
  5. Click the interest rate cell of the latest row and change the value from 4.00 to a valid value such as 7.00.
  6. Click Save and then reopen the record to review the schedule.

Observed behavior:

The reopened record still shows 4.00, which means the change was silently discarded without any message. The same behaviour occurs when editing a non-latest row (for example changing 3.00 to 3.50), when editing the start date, and when setting the rate to 0. Only adding a brand-new row is persisted.

Expected behavior:

Either the latest schedule entry should be editable and the change should be saved, or existing rows should be clearly shown as read-only. Silently reverting the change without any message is misleading, and checklist item UPDATE 7.0 is not met.

LIR-EDIT-existing-row-edit-discarded.png
