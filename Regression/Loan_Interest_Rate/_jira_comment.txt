h2. Loan Interest Rate – Create page: regression findings (Lending Management Entity)

*Environment:* release.intacct.com (server www-p303) | Company SNL_base_303_M | Entity: Lending Management Entity (LME)
*Tested:* 2026-08-01  |  *Total bugs:* 10

h3. Bug #1: Interest rate value of 0 is accepted even though the application states it cannot be zero
*Steps to reproduce:*
# Log in to Sage Intacct (release.intacct.com).
# Switch to the Lending Management Entity using the entity selector.
# Go to Lending Management > Loan interest rates > Create.
# Enter a Name and select Type = Revolving.
# Click "Add row" and set Start date = 07/01/2026.
# Enter Interest rate = 0.
# Click Save.
*Observed behavior:*
The record is saved successfully with Interest rate 0.00 and Status = Active. Note that a negative value (e.g. -5) IS correctly rejected with the message "Interest rate cannot be zero or negative.", so the zero case is inconsistent with the application’s own rule.
*Expected behavior:*
A rate of 0 should be rejected with the message "Interest rate cannot be zero or negative."

h3. Bug #2: Interest rate does not allow 4 decimal places (only 2 are accepted)
*Steps to reproduce:*
# Log in to Sage Intacct (release.intacct.com).
# Switch to the Lending Management Entity using the entity selector.
# Go to Lending Management > Loan interest rates > Create.
# Enter a Name and select Type = Revolving.
# Click "Add row" and set Start date = 08/01/2026.
# Enter Interest rate = 5.1234 (four decimal places).
# Click Save.
*Observed behavior:*
The value is rejected. Only up to 2 decimal places are accepted: both 5.1234 (4 dp) and 5.12345 (5 dp) fail, while 5.12 saves. The backend pattern used is ^(-?\d+)?(\.\d{1,2})?$, which permits a maximum of 2 decimals.
*Expected behavior:*
The interest rate should allow up to 4 decimal places.
*Attachment:* !LIR-CREATE-rate-4decimals-rejected-regex.png|thumbnail!

h3. Bug #5: The "Add row" toolbar button inserts the new row at the top, causing an incorrect date-order error for a later-dated entry
*Steps to reproduce:*
# Log in to Sage Intacct (release.intacct.com).
# Switch to the Lending Management Entity using the entity selector.
# Go to Lending Management > Loan interest rates > Create.
# Enter a Name and select Type = Revolving.
# Click the "Add row" button (top-right of the schedule) and enter Start date = 01/01/2025, Interest rate = 3.00.
# Click the "Add row" button again and observe that the new empty row is inserted ABOVE the existing row.
# In the new (top) row, enter Start date = 02/01/2025 (a date later than the existing row) and Interest rate = 4.00.
# Click Save.
*Observed behavior:*
The save fails with "New Start Date cannot be prior or equal to previous Start Date", even though 02/01/2025 is genuinely later than the existing 01/01/2025. The "Add row" toolbar button always inserts the new row at the TOP, and the grid requires dates in ascending order from top to bottom, so a newly-added later-dated entry fails validation. By contrast, the row-level "+" button inserts the new row at the BOTTOM, and the same dates then save successfully.
*Expected behavior:*
The "Add row" toolbar button should insert the new row at the bottom (consistent with the row-level "+" button), so a later-dated entry can be added without a misleading error. The date-order validation should be based on the actual dates entered, not on the row position in the grid.
*Attachment:* !LIR-CREATE-addrow-top-order-error.png|thumbnail!

h3. Bug #6: Validation and error messages expose internal technical details (regex patterns, JSON field paths and object identifiers)
*Steps to reproduce:*
# Log in to Sage Intacct (release.intacct.com).
# Switch to the Lending Management Entity using the entity selector.
# Go to Lending Management > Loan interest rates > Create.
# Enter a Name, select a Type and click "Add row".
# Trigger any of the following and read the message: (a) Interest rate with more than 2 decimals, e.g. 5.1234; (b) a non-numeric Interest rate, e.g. "abc"; (c) a Name longer than 200 characters.
# Click Save.
*Observed behavior:*
The messages expose internal implementation detail, for example: "The value for the /loanInterestRateEntries/rate field does not match pattern ^(-?\d+)?(\.\d{1,2})?$"; "Not able to set the value abc on field /loanInterestRateEntries/rate"; "Field name value length of object loan-management/loan-interest-rate exceeds the allowed length of 200".
*Expected behavior:*
User-friendly messages should be shown, e.g. "Interest rate can have at most 2 decimal places", "Interest rate must be a number", "Name must be 200 characters or fewer." No internal field paths, object names or regular expressions should be visible to the user.

h3. Bug #7: "Save and new" does not clear the schedule grid
*Steps to reproduce:*
# Log in to Sage Intacct (release.intacct.com).
# Switch to the Lending Management Entity using the entity selector.
# Go to Lending Management > Loan interest rates > Create.
# Enter a Name, select a Type and add a schedule row with a Start date and Interest rate.
# From the Save dropdown, choose "Save and new".
# On the new blank form, expand the "Loan interest rate schedule" section.
*Observed behavior:*
The Name and Type fields reset, but the schedule grid still contains the previous entry’s row (Start date and Interest rate). A user who changes only the Name could unintentionally create a rate that carries the previous schedule.
*Expected behavior:*
"Save and new" should present a completely blank form, including an empty schedule grid.

h3. Bug #10: Untranslated internal keys and an incorrect aria-label appear in the accessibility tree
*Steps to reproduce:*
# Log in to Sage Intacct (release.intacct.com).
# Switch to the Lending Management Entity using the entity selector.
# Go to Lending Management > Loan interest rates > Create.
# Open the Create loan interest rate page and inspect the accessibility tree (or use a screen reader).
# Save a valid record and inspect the success toast’s accessible name.
*Observed behavior:*
Raw internal keys are exposed as accessible names: "IA.COLLAPSE" (the section collapse buttons), "IA.ATTACHMENT" (the schedule Attachment column) and the column headers "ROW_VALIDATION_SUMMARY" / "ROW_MANIPULATION". The success toast "Loan interest rate created" carries the aria-label "IA.MESSAGE_ERROR_LABEL" (an error label key on a success message). The on-screen visible text is correct; the issue is limited to accessible names / screen-reader output.
*Expected behavior:*
All controls should have localised, correct accessible names, and a success message should not use an error label key.

h3. Additional observations
* The date picker allows selecting any day of the month; the "must be the first day of the month" rule is only enforced on Save (a same-form hint or restricting the picker would be friendlier).
* "Save and close" and "Cancel" return to the page the Create screen was opened from (e.g. a record view), not to the Loan interest rates list — confirm the intended landing page.
* Cancel discards unsaved changes immediately with no confirmation prompt.
* Components verified working: Back button, section collapse/expand, Name, Type radios, row-level "+"/"-", date field + calendar picker, Interest rate, Notes, Attachment dropdown (lists attachments), Save / Save and close / Save and new.
