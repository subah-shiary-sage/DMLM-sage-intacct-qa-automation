Defects

Bug #34 [Create - validation]: Required/format validation messages leak internal field paths and raw regex patterns.

Observed behavior:

Several mandatory fields do not produce friendly "required" messages; instead the server returns raw internal identifiers:
• Order Entry transaction definition left blank → "The value for the order-entry-txn-definition.key field does not match pattern /^(-?\d+)$/".
• A Payment priority order row with a blank Type → "The value for the /loanInvoiceOrders/loanInvoiceLineType field is not in valid values list" and "Not able to set the value '' on field loanInvoiceLineType".
By contrast, the Loan type and Interest type fields DO show friendly "Field is required." messages, so the behaviour is inconsistent.

Expected behavior:

All required/format errors should be user-friendly and name the on-screen field, e.g. "Order Entry transaction definition is required." and "Type is required." - with no internal object/field paths or regular expressions.

Attachment:

Saving with Order Entry transaction definition blank shows the internal field name + raw regex pattern.

Bug #35 [View]: The loan type detail (view) page heading shows the internal record ID instead of the loan type name.

Observed behavior:

After creating/opening a loan type, the detail page H1 heading reads "Loan type: 13" (the internal record ID) even though the record's name is "QA LT ValTest 001". The name is only shown lower down in the body.

Expected behavior:

The detail heading should read "Loan type: <Name>", e.g. "Loan type: QA LT ValTest 001".

Attachment:

Detail heading "Loan type: 13" uses the internal ID, not the loan type name.

Bug #36 [UI labels / accessibility]: Untranslated resource keys are used as accessibility labels (IA.MESSAGE_ERROR_LABEL, IA.COLLAPSE, IA.TOGGLE_BUTTON_LABEL).

Observed behavior:

Several controls carry raw untranslated resource keys as their accessibility (aria) labels: the error banner aria-label is "IA.MESSAGE_ERROR_LABEL", every section collapse button is "IA.COLLAPSE", and the list view toggle group is "IA.TOGGLE_BUTTON_LABEL". Screen-reader users hear the raw keys. (Same class of issue seen in the Loan Account / Loan Category modules.)

Expected behavior:

These aria-labels should resolve to their translated strings (e.g. "Error", "Collapse section", "Toggle view").

Attachment:

The red error banner's accessibility label is the raw key "IA.MESSAGE_ERROR_LABEL".

Additional observations (minor)

  • Payment priority order - Sort order is not auto-sequenced. The checklist expects the Sort order to be filled sequentially (1, 2, 3...) as rows are added; in practice every newly added row has a blank Sort order that must be typed manually (verified by adding three rows). Marked Failed on the checklist (row 92).
  • "Loan invoicing defaults" section is expanded by default. The checklist expects this section to be collapsed by default; the app renders it expanded. Marked Failed on the checklist (row 58) - likely a design choice rather than a defect.
  • Grid business rules not exercised. The one-Principal / one-Interest / multiple-Fee row rules and some blank-item error paths could not be reliably automated because the grid lazily renders extra rows; these are marked Untested on the checklist.
