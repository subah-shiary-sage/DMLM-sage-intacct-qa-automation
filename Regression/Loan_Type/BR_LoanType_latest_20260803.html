Defects

Bug #39 [Create - Payment priority order]: Selecting Fee as a row Type without a Fee type produces a raw internal error.

Observed behavior:

Adding a Payment priority order row with Type = "Fee" but no Fee type selected, and clicking Save, shows the raw error "loan-management/loan-type has a id 27 with invalid values. Consult the online manual for the valid range of values for id." - an internal message that leaks the object name and an internal id and points the user to a manual.

Expected behavior:

A clear field-level message such as "Fee type is required for a Fee line." (matching row 108 of the checklist).

Attachment:

Fee row without a Fee type -> raw internal "invalid values / online manual" error.

Bug #40 [View - 3-dot menu]: The view-page 3-dot (More actions) menu is missing "Object definition".

Observed behavior:

On the loan type detail page the 3-dot "More actions" menu contains only "View audit trail". The expected "Object definition" entry is absent (checklist rows 165/167).

Expected behavior:

The 3-dot menu should contain both "View audit trail" and "Object definition".

Attachment:

3-dot menu shows only "View audit trail" - "Object definition" is missing.

Additional observations (checklist Failed - minor)

  • Sort order is not auto-sequenced (row 84). New Payment-priority rows get a blank Sort order that must be typed; the checklist expects 1, 2, 3... automatically.
  • Sort order accepts non-numeric input (row 86). Typing "9abc7" into a Sort order of "1" produced "9abc71" - the field is not restricted to numeric characters.
  • "Loan invoicing defaults" is expanded by default (row 50) where the checklist expects it collapsed (likely a design choice).
  • Edit heading exposes the internal object path (row 207). It reads "Edit loan-management/loan-type: 15--revolving-simple-a365" rather than the checklist's expected "Edit loan-type: <ID>--<name>".
  • Untranslated aria-labels - the error banner ("IA.MESSAGE_ERROR_LABEL"), section collapse buttons ("IA.COLLAPSE") and list toggle ("IA.TOGGLE_BUTTON_LABEL") use raw resource keys as accessibility labels.

Not tested (blocked)

  • Multi-entity validation (rows 264-266). Switching to the "Top level" opens a separate classic-UI session/tab (COOP-restricted); full cross-entity create -> view -> edit/delete verification could not be reliably automated. Recommend manual verification.

What works well

  • Type-specific payment-priority rules are correctly enforced: Revolving requires an Interest row; Non-revolving requires both a Principal and an Interest row ("Payment priority order should contain both principal and interest item for Non-revolving loan type"); duplicate Interest rows are rejected ("should not contain multiple interest types"); an empty grid is rejected ("At least one Payment priority order line item is required").
  • Conditional interest logic is correct: the Interest calculation method appears only after a Type is chosen and is filtered by it (Revolving -> Actual/365, Actual/360; Non-revolving adds 30/360); switching Type resets it.
  • Edit page is well-behaved: Type is read-only, the Save dropdown correctly drops "Save and new" (only Save / Save and close), Status is an editable Active/Inactive dropdown and a status change persists to the view page.
  • Delete uses a proper confirmation modal and removes the record with a "Loan type deleted" toast. Friendly required-field messages are shown for Loan type and Interest type.
