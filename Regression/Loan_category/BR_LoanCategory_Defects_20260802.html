Defects

Bug #28 [View]: View page heading shows "Loan account categories: <ID>" (plural noun + internal record ID) instead of the record name.

Observed behavior:

Opening any loan account category detail page shows the H1 heading as "Loan account categories: 24" - the plural list noun followed by the internal record ID - instead of the category name. Example: the category named "Loan Cat DocSeq 01" displays "Loan account categories: 24".

Expected behavior:

The detail heading should read "Loan account category: <Name>" (singular noun + the record's Name), e.g. "Loan account category: Loan Cat DocSeq 01".

Attachment:

View page heading reads "Loan account categories: 24" (plural + internal ID) instead of the category name.

Bug #29 [Edit]: Edit page heading exposes the raw internal object path "Edit loan-management/loan-category: <ID>--<Name>".

Observed behavior:

The edit page H1 heading reads "Edit loan-management/loan-category: 24--Loan Cat DocSeq 01" - it exposes the internal object path "loan-management/loan-category" and the internal record ID to the end user.

Expected behavior:

The edit heading should read "Edit loan account category: <Name>" (a friendly label), e.g. "Edit loan account category: Loan Cat DocSeq 01".

Attachment:

Edit heading exposes the internal object path "loan-management/loan-category" and record ID.

Bug #30 [Create / Edit - validation]: Field validation error messages leak the internal object name "object loan-management/loan-category".

Observed behavior:

Several validation errors expose the internal object name instead of a friendly message. Examples: whitespace-only name -> "A value is required for the field name of object loan-management/loan-category"; name over 200 chars -> "Field name value length of object loan-management/loan-category exceeds the allowed length of 200 ... is not in the required format"; description over 500 chars -> "Field description value length of object loan-management/loan-category exceeds the allowed length of 500". This occurs on both the create and edit forms.

Expected behavior:

User-friendly messages that name the field, not the internal object - e.g. "Name is required.", "Name cannot exceed 200 characters.", "Description cannot exceed 500 characters."

Attachment:

Description length error leaks "object loan-management/loan-category".

Bug #31 [View - 3-dot menu]: The 3-dot (More actions) menu on the view page is missing the "Object definition" item.

Observed behavior:

On the category detail page the 3-dot "More actions" menu contains only "View audit trail". The expected "Object definition" entry is absent.

Expected behavior:

The 3-dot menu should include both "View audit trail" and "Object definition" (as specified for the module).

Attachment:

3-dot menu shows only "View audit trail" - "Object definition" is missing.

Bug #32 [UI labels / accessibility]: Untranslated resource keys are used as accessibility labels (IA.MESSAGE_ERROR_LABEL, IA.COLLAPSE, IA.TOGGLE_BUTTON_LABEL).

Observed behavior:

Several controls carry raw untranslated resource keys as their accessibility (aria) labels instead of readable text: the error/toast banner aria-label is "IA.MESSAGE_ERROR_LABEL", the section collapse button aria-label is "IA.COLLAPSE", and the list view toggle group aria-label is "IA.TOGGLE_BUTTON_LABEL". Screen-reader users hear the raw keys.

Expected behavior:

These aria-labels should resolve to their translated strings (e.g. "Error", "Collapse section", "Toggle view").

Attachment:

The red error banner's accessibility label is the raw key "IA.MESSAGE_ERROR_LABEL".

Bug #33 [Create]: Creating a category with a duplicate name shows the unfriendly error "[object Object]".

Observed behavior:

Attempting to save a new category using a name that already exists (e.g. "Loan Cat DocSeq 01") returns the error banner text "[object Object]" (the server responds HTTP 500). The user is given no indication that the problem is a duplicate name.

Expected behavior:

A clear, human-readable message such as "A loan account category with this name already exists. Please use a unique name."

Attachment:

Duplicate category name yields the error "[object Object]".
